# Development

## Make targets

This repo is managed by [bmk](https://github.com/bitranox/bmk) (its Makefile begins
with `# BMK MAKEFILE <version>` and is regenerated by bmk itself; do not hand-edit it).
Run `make help` for the authoritative, current target list with one-line descriptions;
it greps the Makefile's own comments, so it never disagrees with what actually runs.
`bmk --help` / `bmk <command> --help` documents the underlying CLI.

The everyday targets:

```bash
make test          # ruff lint + format check, pyright strict, bandit, pytest with coverage
make dev           # editable install with dev extras
make build         # wheel/sdist artifacts
make bump-patch    # bump patch version (X.Y.Z -> X.Y.(Z+1)); also bump-minor / bump-major
make push          # run tests, commit, push to the remote
make release       # tag and create a GitHub release for the current pyproject version
make clean         # remove caches, build artifacts, coverage
```

`make test` is the single pre-push gate; never reproduce it as a hand-picked subset of
ruff/pyright/pytest, since bmk also runs whole-tree Markdown formatting and
`import-linter`.

## Versioning & metadata

- Single source of truth for package metadata is `pyproject.toml` (`[project]`).
- `src/btx_lib_mail/__init__conf__.py` is generated from `pyproject.toml`; do not
  hand-edit the version there.
- `make bump-patch` / `make bump-minor` / `make bump-major` update `pyproject.toml`,
  `src/btx_lib_mail/__init__conf__.py` and `.claude-plugin/plugin.json` to the new
  version, and insert a new `CHANGELOG.md` section; `make release` tags and releases
  the CURRENT `pyproject.toml` version without bumping it, so bump first if the version
  is not yet released.

## Dependency auditing

`make test` runs `pip-audit` against the resolved project environment as part of the
gate. Check `pyproject.toml` for any `# pip-audit ignore` comments explaining a
suppressed finding and its re-enable condition; do not add a blanket ignore.

## CI & publishing

`.github/workflows/` is distributed from the `default_cicd_public` CI template and is
off-limits to hand-edits here (a manual change is silently reverted by the next
template distribution; edit the template and run its `distribute.sh` instead):

- `default_cicd_public.yml` - lint/type/test across the Python and OS matrix declared in
  `pyproject.toml` (`Programming Language :: Python :: X.Y` classifiers, `[tool.ci].os`).
- `default_release_public.yml` - on a version tag, builds and publishes to PyPI using a
  `PYPI_API_TOKEN` secret when set, otherwise an OIDC Trusted Publisher.
- `codeql.yml` - CodeQL scanning.

To publish a release: bump the version (`make bump-patch`/`-minor`/`-major`), update
`CHANGELOG.md`, then `make release` (tags the current version and triggers the release
workflow). Do not push, tag, or release without the maintainer's explicit go.

## Codecov uploads

`make test` (coverage on by default) generates `coverage.xml` and uploads it to Codecov
when configured. Set `CODECOV_TOKEN` in `.env` (gitignored; see `.env.example`) for a
private repo; a public repo typically needs no token.
